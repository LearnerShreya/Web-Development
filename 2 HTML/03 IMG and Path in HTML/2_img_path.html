Types of Paths

In computer file systems, paths are used to specify the location of files and directories. There are primarily two types of paths: Relative Paths and Absolute Paths.

1. Relative Path

A relative path specifies the location of a file or folder in relation to the current working directory. It provides flexibility when referencing files within a project, especially when moving projects to different locations.

Example:
./images/photo.jpg - This path points to a file named photo.jpg located in the images folder within the current directory.

Another example is:
../assets/style.css - This path points to style.css located in the assets folder, which is one level up from the current directory.

Here are two specific examples of relative paths used for images:

  • <img src="../../2 HTML/03 IMG and Path in HTML/acharya.png" height="100" width="100" alt=""> - This path goes two directories up from the current directory to find acharya.png.
  • <img src="WsCube Tech.png" height="100" width="100" alt="WsCube Tech"> - This path accesses WsCube Tech.png located in the same directory as the HTML file.

2. Absolute Path

An absolute path provides the complete address to a file or folder, starting from the root directory. This type of path is unambiguous and allows direct access to files regardless of the current working directory.

Examples:
Windows: C:/Users/Shreya/Documents/images/photo.jpg
Linux/Mac: /home/shreya/documents/images/photo.jpg

Absolute paths are often used in scripts or configurations where the exact location of the file is crucial.

3. Network Path

A network path is used to specify the location of files on a network. It typically includes the name of the server and the path to the resource on that server.

Example:
\\ServerName\SharedFolder\document.docx - This path points to document.docx stored in the SharedFolder on the server ServerName.

4. URL Path

A URL path is used to specify the location of resources on the internet. It includes the protocol (like HTTP or HTTPS) followed by the domain name and the path to the resource.

Example:
https://www.example.com/images/photo.jpg - This URL points to photo.jpg stored in the images folder on the website example.com.

Why Three Dots Are Not Allowed

Using three dots (e.g., `...`) is not a valid notation in file paths. Paths should only use a single dot (`.`) for the current directory and double dots (`..`) for the parent directory. Three dots can create confusion and are not recognized by file systems as a legitimate path structure.

Note: Why We Don't Allow Access from the Root Directory

The root directory is the highest level in a file system hierarchy. It contains all other directories and files. Accessing files directly from the root directory can pose several risks and challenges:

  • Security Concerns:
    • Vulnerability to Attacks: Allowing access to sensitive files can lead to data breaches if unauthorized users exploit them.
    • Risk of File Manipulation: Users may modify critical system files, leading to system instability or failures.
  • User Permissions:
    • Limited Access Control: Users might gain more access than necessary, which can be risky.
    • Difficulties in Auditing: Monitoring changes to important files becomes more challenging, making it hard to track unauthorized access.
  • File Organization:
    • Clutter and Confusion: Allowing root access can lead to a messy file structure that users find hard to navigate.
    • Namespace Conflicts: Different files may have the same name, leading to errors when referencing them.
  • Separation of Concerns:
    • Encapsulation: Keeping files organized within specific directories promotes a clearer file structure.
    • Easier Maintenance: Changes to one area can be made without affecting unrelated files, simplifying updates.
  • Best Practices:
    • Industry Standards: Limiting access to necessary directories is a widely accepted security practice.
    • Compliance: This approach helps adhere to regulations regarding the protection of sensitive information.

Conclusion

For these reasons, it's important to limit access to specific directories that are essential for user tasks. This practice enhances security and improves overall system organization.

Brief Description of Root Directory and Directories

Root Directory

The root directory is the top-level directory in a file system. It serves as the starting point from which all other directories branch out. For example, in a Windows system, the root directory for the C: drive is represented as C:\. This directory may contain subdirectories such as Documents, Program Files, and Users.

Directories

A directory is a container that holds files and other directories. They help organize files in a hierarchical manner. For example, within the root directory, you might have a directory structure like this: 

C:\
├── Users
│   ├── Neha
│   └── Gaurav
├── Program Files
└── Windows

In this structure, Users, Program Files, and Windows are all directories contained within the root directory, helping to keep the file system organized and manageable.
