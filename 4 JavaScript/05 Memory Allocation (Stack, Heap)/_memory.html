Memory Allocation in JavaScript

JavaScript handles memory through two primary areas: the Stack and the Heap. The Stack is used for static memory allocation (primitive values and function calls), while the Heap is used for dynamic memory allocation (objects and arrays).

1. Stack vs Heap Memory

JavaScript uses stack for storing static data and heap for storing dynamic objects.

Stack

  • Stores data sequentially with a predictable order.
  • Contains fixed-size data: primitives, function calls, and references to heap objects.
  • Fast access due to the Last-In-First-Out (LIFO) structure.
  • Memory is automatically managed, making it efficient.
  • Limited in size, typically smaller than the heap.
  • Prone to stack overflow when there are too many function calls or large local variables.
  • Thread-specific: Each thread in a multi-threaded environment gets its own stack.

Heap

  • Stores data in a random order, not sequential.
  • Slower access due to memory being scattered.
  • Used for dynamic, flexible-size objects such as arrays and objects.
  • Relies on garbage collection to free up unused memory.
  • Prone to memory leaks if objects are improperly referenced.
  • Allows for global access if references are passed.
  • Memory fragmentation may occur due to scattered allocations.
  • Supports complex relationships (e.g., arrays inside objects).

Code Example: Stack and Heap Behavior

    // Stack Example
    let num = 10;       // Primitive stored in stack
    let str = "Hello";  // Primitive stored in stack

    // Heap Example
    let obj = {         // Object stored in heap
        name: "Shreya",
        age: 21
    };
    let arr = [1, 2, 3]; // Array stored in heap

    // Reference Example
    let ref = obj;      // Both 'obj' and 'ref' point to the same heap memory
    ref.age = 22;       // Changes affect both 'obj' and 'ref'
    console.log(obj.age); // Output: 22

Key Takeaways

Stack:

  • Predictable and fast memory usage.
  • Used for primitives, function calls, and references.

Heap:

  • Flexible, larger memory space for dynamic objects.
  • Ideal for complex data structures and relationships.

2. Call by Value vs Call by Reference

JavaScript uses two ways of passing data:

  • Call by Value: For primitives, only the value is copied, creating independent variables.
  • Call by Reference: For objects and arrays, only the memory reference is copied, so changes affect the original data.

Example

// Call by Value
let num = 10;
function modifyValue(x) {
    x = 20;
}
modifyValue(num);
console.log(num); // Output: 10 (Unchanged)

// Call by Reference
let obj = { name: "Shreya" };
function modifyReference(o) {
    o.name = "Gaurav";
}
modifyReference(obj);
console.log(obj.name); // Output: "Gaurav"

3. Mutable vs Immutable

Mutable: Data that can be modified after creation (e.g., objects, arrays).

Immutable: Data that cannot be modified after creation (e.g., strings, numbers, booleans, etc).

Example

// Mutable Example
let arr = [1, 2, 3];
arr.push(4);
console.log(arr); // Output: [1, 2, 3, 4]

// Immutable Example
let str = "Hello";
str[0] = "h";
console.log(str); // Output: "Hello" (unchanged)

4. Garbage Collection

JavaScript uses an automatic garbage collection process to remove objects that are no longer referenced, freeing up memory.

  • Garbage collection uses the mark-and-sweep algorithm.
  • Objects without any references are marked as "garbage."
  • This prevents memory leaks by cleaning up unused memory.

5. Memory and File Deletion

When files or folders are deleted in a computer system, the following steps occur:

  • The operating system removes the file's metadata (e.g., file name, size, and location) from the file system, marking the space as free.
  • The space previously occupied by the file is marked as free and available for new data.
  • The actual data remains on the disk until it is overwritten by new files or data.
